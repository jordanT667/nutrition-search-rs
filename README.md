# nutrisearch

![ci](https://github.com/jordanT667/nutrition-search-rs/actions/workflows/ci.yml/badge.svg)

**Ask the French dietary guidelines a question, get the pages that answer it, in about 50 to 80 µs.**

A from-scratch Rust port of the BM25 retriever of [nutrition-rag](https://github.com/jordanT667/nutrition-rag),
my question-answering assistant on the Santé publique France guidelines (2019). Same text folding, same tokens,
same formula and constants as the Python version (`rank_bm25.BM25Okapi`), and the tests check it:
**the 50 evaluation questions × 151 passages give the same scores in Rust and Python, to 10⁻⁹.**

```
❯ Combien de poisson faut-il manger par semaine ?
  mots cherchés : poisson · manger · semaine   ·   151 passages en 107 µs

   1  p.34   ██████████████ 7.42
      … privilégiez les féculents bio. → Le poisson Recommandation principale : Deux fois par semaine du …
      pourquoi : poisson +5.42  semaine +1.99

   2  p.20   ██████████████ 7.26
      … secs dans le groupe « viande, poisson et œufs » avait retenu fortement l'attention des …
      pourquoi : poisson +3.83  manger +3.43
```

In a terminal, the matching words are highlighted and the first result is shown in red. Each result says
**why** it ranks there: the contribution of each query word to the BM25 score.

## Results

Retrieval on the 40 answerable questions of `eval/questions.jsonl` (written for nutrition-rag):

| | hit@1 | hit@3 | hit@5 | hit@8 | MRR |
|---|---|---|---|---|---|
| Python, nutrition-rag (`reports/retrieval_summary.csv`) | 0.700 | 0.900 | 0.950 | 0.950 | 0.811 |
| Rust, `nutrisearch eval` | 0.700 | 0.900 | 0.950 | 0.950 | 0.811 |

Identical, as expected from identical scores. The port changes the speed, not the answers.

Speed on my laptop (Windows 11, release build, one core, 3 runs each, same 50 questions, top 5):

| | per query | queries per second |
|---|---|---|
| Python (`rank_bm25` + NumPy, `tools/reference.py`) | 671 to 1,020 µs | 981 to 1,491 |
| Rust (`nutrisearch bench`) | 53 to 78 µs | 12,768 to 18,783 |

About 10 to 15 times faster per query. These are timings on a busy laptop, not a controlled benchmark.

## How it works

- `fold`: lowercase, `œ` → `oe`, `æ` → `ae`, NFKD and accents dropped.
- `Tokenizer`: `[a-z0-9]+` runs, French stopwords and one-letter words removed, light plural stemming (`légumes` → `legume`).
- `Bm25`: Okapi BM25 with k1 = 1.5, b = 0.75. As in `rank_bm25`, a word present in more than half of the
  passages would get a negative IDF; it is replaced by 0.25 × the mean IDF.
- `Index::search`: scores every passage, sorts by score (ties by position in the document), keeps the top k.
- `Bm25::explain`: splits a passage's score into the contribution of each query word.

No dependency beyond `serde`, `serde_json` and `unicode-normalization`.

## Usage

The passages are built by nutrition-rag from the official PDF and are not redistributed here.

```bash
git clone https://github.com/jordanT667/nutrition-rag
git clone https://github.com/jordanT667/nutrition-search-rs
cd nutrition-rag && pip install -r requirements.txt && python -m src.nutrirag.ingest && cd ..
cd nutrition-search-rs && cargo build --release

./target/release/nutrisearch "combien de poisson par semaine ?"
./target/release/nutrisearch            # interactive mode
./target/release/nutrisearch eval
./target/release/nutrisearch bench
./target/release/nutrisearch --json -k 3 "eau"
```

`--passages PATH` (or `NUTRISEARCH_PASSAGES`) points to another `passages.json`; `NO_COLOR=1` gives plain output.

## Tests

`cargo test` runs:

- unit tests on folding, tokens, the IDF floor and the explanations;
- `tests/search.rs`: search and evaluation behaviour on a 3-passage corpus (top-k cut, ties kept in
  document order, repeated and unknown query words, explanations, hit@k and MRR with unanswerable
  questions left out);
- `tests/parity.rs`: the scores on a 3-passage corpus must match those exported from Python
  (`tests/fixtures/small.json`, runs in CI), and, when the real corpus and `target/python_scores.json`
  are present (`python tools/reference.py`), the scores of all 50 questions on all 151 passages.

CI runs `cargo fmt --check`, `cargo clippy -D warnings` and `cargo test` on every push.

## Limits

- Lexical search only: a question with none of the document's words finds nothing (synonyms, paraphrases).
  2 of the 40 answerable questions have no right page in the top 5.
- The questions were written after reading the document, so the scores are optimistic for real users.
- This is the retrieval step only; the answers with citations are generated by nutrition-rag.
